## 核心结论

1. 研究不应直接声称从 corporate sustainability reports 自动完成严格 product-level LCA，而应定位为将报告转化为可审计的 LCA-relevant evidence layer。
2. 系统核心应是 Evidence Objects：每条证据包含 concept、source page、evidence text、metadata、embedding、provenance、applicability 和 audit flags。
3. Ontology / glossary 用于约束抽取和 concept matching；LLM 不应自由生成无来源结论。
4. Knowledge Graph 应采用 lazy loading：先保存 CSV / database、metadata、embedding 和 provenance；查询或可视化时再按 top-k 生成局部图。
5. Scope 3 为空不是系统失败，而是 disclosure gap / missing evidence 输出。
6. 实验阶段先用小样本证明 framework 和 metrics，不需要一开始处理 20,000 份报告。
7. 评价重点包括 extraction accuracy、schema matching、LCA applicability、grounding、auditability、efficiency 和 disclosure-risk indicators。
8. API/token 成本可申请 HDR Support Scheme 支持。

## 对研究 framing 的影响

会议将研究主张从 “automated LCA from reports” 调整为 “provenance-aware evidence engine for LCA-relevant report analysis”。这降低了过度承诺风险，也让研究贡献更容易被实验评估。

## 对系统架构的影响

- Evidence Object 成为系统原子单位。
- Lazy KG 替代全量预构建 KG。
- Missing evidence detection 被纳入 auditability。
- NAICS-aware comparison 用于公平评估不同行业报告。

## 对实验设计的影响

建议 pilot benchmark 使用 10–20 份报告，覆盖多个 NAICS sectors；人工标注重点章节，包括 Scope 3、supply chain、energy、materials、water、waste、S-LCA、net-zero / target claims。实验比较 keyword/rule-based、vanilla LLM、RAG+LLM、ontology-guided provenance-aware pipeline。
